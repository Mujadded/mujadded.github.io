# Dataset shift & robustness — a method demo

**This is a demonstration of a technique, on synthetic data. It is not a
reproduction of any real project's results.** The [Edge CV case
study](../../case-studies/edge-cv-outdoor-inspection.html) on this site
describes work on private client inspection data; nothing from that data,
and none of its numbers, appear here. This demo generates its own tiny
dataset from a fixed random seed, trains on it, and prints whatever comes
out — that is the whole point: you can get the exact same numbers by
running it yourself.

## The idea

A model trained only on clean images tends to look great in testing and then
degrade sharply the moment the input distribution shifts even a little —
sensor noise, a blurred frame, a lighting change. That's the failure mode
the site's [Edge CV Under Domain Shift](../../posts/2026-01-27-edge-cv-domain-shift.html)
post discusses in the context of real deployments. This demo isolates the
same mechanism down to something anyone can run in under a minute on a
laptop CPU:

1. Train a small CNN to classify four synthetic shapes (circle, square,
   triangle, cross), rendered with PIL, on **clean** images only.
2. Test it on a **clean** held-out set (expect it to do fine) and on a
   **shifted** held-out set — the same shapes with Gaussian noise, blur, and
   a brightness/contrast change applied (expect it to do much worse).
3. Train a second model identically, except 50% of its training images also
   have that same shift applied — i.e. it has seen the shift before.
4. Compare all four numbers.

Everything — the shapes, the shift, the training, the numbers — is
generated by `demo.py` at run time. There is no dataset file, no download,
and no GPU requirement.

## Run it

```bash
pip install -r requirements.txt
python demo.py
```

Takes well under a minute on CPU. Sample output (yours will match exactly —
the seed is fixed):

```
model                          clean test   shifted test
----------------------------------------------------------
baseline (clean-only train)         82.7%          32.7%
robust (shift-augmented)            71.8%          56.5%
```

Read it as: the baseline model loses ~50 points of accuracy the moment the
input shifts. Training with that shift already present recovers a large
chunk of it, at a real cost — the robust model is a bit worse on clean data
too. That trade-off is the point; a demo where the fix was free would not be
an honest one.

## Tweaking it

`SEED`, `NOISE_STD`, `BLUR_RADIUS`, `BRIGHTNESS_DELTA`, `CONTRAST_SCALE`,
`EPOCHS` are constants at the top of `demo.py`. Change one and re-run to see
how sensitive the recovery gap is to how severe the shift actually is — it
isn't a fixed law, and this demo doesn't pretend it is.

## What this demo is not

- Not a benchmark. Four shapes on a 32x32 canvas is a toy problem, on
  purpose — the mechanism it isolates (shift breaks accuracy, exposure to
  shift during training recovers some of it) is real; the specific numbers
  above are not evidence of anything beyond this toy task.
- Not the case study. The real inspection work referenced elsewhere on this
  site used private client data that isn't published anywhere, this demo
  included.
- Not tuned for a good headline number. The severity constants were picked
  to make the effect visible by eye, not to maximize the "robust" model's
  score.
